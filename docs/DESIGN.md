# 薄荷工坊 UI 设计规范

> 版本：2.0
> 设计方向：霓雾科技玻璃（Aurora Mist Glass）
> 视觉基准：用户确认的 1440 × 1024 三列工作台设计稿
> 适用范围：定义视觉、布局、组件状态与草稿删除入口；除文档明确说明外，不改变现有生成流程、数据语义或用户确认边界。

## 1. 设计结论

薄荷工坊采用 **“霓雾科技玻璃”** 作为新的主视觉方向：以深靛蓝和烟紫色创作空间为背景，用蓝紫、青色和玫粉光轨制造景深；功能内容承载在低不透明度的雾面玻璃中，并保留圆润、可触摸的 3D Claymorphism 品牌特征。

该方向不是传统深色后台，也不是高对比霓虹赛博界面。页面应同时具备：

- 科技感：蓝粉光轨、冷色边缘折射、轻量状态光点和清晰的数据层级。
- 雾面玻璃感：背景可透出，文字区域有充分模糊和局部遮罩，不使用大块实色面板。
- 创作感：核心视觉围绕笔记本、铅笔、内容缩略图和创作流程，不使用无关的工业仪表或代码装饰。
- 黏土感：头像、笔记本和关键图标保留圆润的 3D soft icon 质感。
- 可操作性：当前步骤、主要动作、搜索勾选、RAG 入库、模型配置和错误状态应在 2 秒内被识别。

一句话视觉定义：**像一张漂浮在蓝紫极光中的创作控制台——通透、有速度感，但内容始终比光效更清楚。**

## 2. 设计边界

### 2.1 必须保持

- 固定三列工作台：左侧流程与草稿，中间阶段式创作区，右侧模型配置、连接状态与错误提示。
- 人设、关键词、撰写思路和模型配置的自动缓存。
- 用户主动点击搜索、检测、生成和“自动化生成”的触发方式。
- 搜索结果手动勾选与 RAG 入库确认边界。
- 10 个选题、5 篇文案、5 份封面 Prompt 和封面图的生成流程。
- 文案生成模型与图片生成模型独立配置。
- xhs、Codex、云端文本 API 三路连接检查的真实校验语义。
- 不新增自动发布、自动点赞、自动评论、自动收藏、自动关注、自动私信或后台自动采集。

### 2.2 本版明确变化

- 产品视觉从浅色马卡龙面板升级为蓝紫霓雾背景上的低透明度科技玻璃。
- 左上助手区加入卡通女生头像。
- 助手区只保留“内容创作助理”，删除原有“本地草稿”一行；本地草稿能力仍由下方“草稿项目”承载。
- 草稿卡片右侧使用“×”删除入口，不再使用“···”菜单。
- 草稿删除属于后续交互能力：实现时必须提供二次确认、删除目标名称和取消操作；本设计文档不代表该功能已经完成。

## 3. 空间与背景

页面由四层空间组成：

1. **环境底图**：全屏深靛蓝、烟紫与钴蓝背景，允许包含抽象创作空间、柔焦桌面或远景光带。
2. **极光层**：右上方向下延伸玫粉光束，中部具有蓝紫弧形光轨，底部保留少量钴蓝反射。
3. **雾幕层**：对背景统一压暗与模糊，控制局部亮度，避免文字直接落在高频图像上。
4. **内容玻璃层**：顶部栏、三列主容器和内部功能区使用三档透明度建立层级。

### 3.1 背景构图

- 主色为深靛蓝与烟紫，画面右上保留一束清晰但柔和的玫粉光流。
- 中央概览区可展示粉紫 3D 笔记本与铅笔，底部使用蓝粉同心光环承托。
- 背景可以有少量颗粒、薄雾和光带，但不得使用密集网格、代码雨、星空粒子墙或高频 HUD 装饰。
- 背景图不出现真人、真实人脸、手、动物或可辨识品牌 Logo。
- 小红书搜索结果缩略图由真实数据决定，不受背景图人物限制；封面生成仍遵守“不含真人、脸、手和动物”的产品约束。

### 3.2 背景动势

- 默认背景为静态视觉资产，不自动联网换图。
- 可使用 CSS 对独立光层做 12–18 秒的低速位移或亮度呼吸，位移不超过 3%，透明度变化不超过 8%。
- 动势集中在背景光轨与当前阶段指示，不移动功能面板，不制造布局漂移。
- `prefers-reduced-motion: reduce` 下关闭背景位移和循环呼吸。

## 4. 色彩系统

### 4.1 核心色

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| 宇宙墨 `Space Ink` | `#080B2A` | 页面最深背景、底部压暗 |
| 深海靛 `Deep Indigo` | `#151B55` | 主玻璃底色、输入区底色 |
| 烟紫 `Mist Plum` | `#5A4776` | 玻璃暖侧、右栏背景折射 |
| 电光蓝 `Electric Blue` | `#557DFF` | 当前步骤、信息状态、边缘折射 |
| 极光青 `Aurora Cyan` | `#62E6DE` | 主操作、成功、自动缓存、流程推进 |
| 霓虹紫 `Neon Violet` | `#9D64FF` | 选中态、阶段光轨、次级操作 |
| 玫粉 `Rose Beam` | `#F260B5` | 图片生成、强调按钮、右上环境光 |
| 珊瑚红 `Coral Alert` | `#FF6F78` | 错误、阻断与删除确认 |
| 云雾白 `Cloud White` | `#F4F5FF` | 深色玻璃上的主文字 |
| 薰衣草灰 `Lavender Gray` | `#B8B9D6` | 次级文字、非活动状态 |

颜色使用原则：

- 同一功能区最多出现一个主强调色和一个状态色。
- 极光青继续承担品牌主操作，不把所有按钮改成紫粉渐变。
- 玫粉和电光蓝主要用于背景、封面图生成、当前阶段边缘和少量高亮。
- 错误状态必须使用珊瑚红图标、文字或状态线，不只靠色相区分。

## 5. 玻璃、边缘与阴影

同一视图只使用三档玻璃强度：

| 层级 | 典型区域 | 背景不透明度 | 模糊 |
| --- | --- | --- | --- |
| 强玻璃 | 左栏、中央主容器、右栏 | 48–56% | 26–32px |
| 中玻璃 | 人设区、搜索/RAG 区、模型分组 | 34–42% | 22–28px |
| 软玻璃 | 输入框、步骤卡、列表行、计数卡 | 22–32% | 16–22px |

主面板参考材质：

```css
background:
  linear-gradient(145deg, rgba(61, 66, 132, 0.46), rgba(18, 24, 71, 0.50));
border: 1px solid rgba(229, 232, 255, 0.20);
box-shadow:
  0 22px 54px rgba(4, 7, 30, 0.28),
  inset 0 1px 0 rgba(255, 255, 255, 0.18),
  inset 0 -1px 0 rgba(8, 11, 42, 0.20);
backdrop-filter: blur(28px) saturate(132%);
```

使用规则：

- 背景必须能够透过面板被感知，不能把功能区做成不透明深色矩形。
- 轮廓以 1px 冷白边缘为主，当前区域允许增加青蓝折射，不使用 2px 以上霓虹描边。
- 阴影范围大、浓度低，不使用纯黑硬阴影。
- 高亮区域可以有蓝紫或玫粉内反射，但发光不得影响正文对比度。
- 不支持 `backdrop-filter` 时，使用不透明度更高的深靛底色作为降级方案。

## 6. 布局系统

### 6.1 桌面结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 品牌 / 全局搜索 / 通知 / 帮助 / 用户                                │
├──────────────┬────────────────────────────────────┬──────────────────┤
│ 左侧工作流   │ 中央阶段式创作区                   │ 右侧模型与状态   │
│ 220–240px    │ minmax(720px, 1fr)                 │ 300–320px        │
│              │                                    │                  │
│ 助手头像     │ 创作概览 + 关键数量                │ 文案生成模型     │
│ 创作流程     │ 人设与关键词                       │ 图片生成模型     │
│ 草稿项目     │ 搜索结果 / RAG / 后续阶段结果      │ 三路连接检查     │
└──────────────┴────────────────────────────────────┴──────────────────┘
```

- 设计基准为 1440 × 1024；浏览器验收同时覆盖 1440 × 900 和 1366 × 768。
- 页面外边距 14–20px，列间距 12–16px。
- 左栏建议 230px，右栏建议 300px，中央区域获得剩余宽度且不得小于 720px。
- 三列各自滚动，顶部栏保持在视觉最上层。
- 中央内容内部使用 12 列网格；人设/关键词、搜索/RAG、文案/预览、Prompt/封面继续成对展示。
- 125% 与 150% 系统缩放下允许整体横向滚动，但不能压缩到遮挡按钮或字段。

### 6.2 形状与间距

- 顶部栏和三列外壳：24–28px 圆角。
- 中央概览与主要分区：18–22px 圆角。
- 输入框、步骤卡和列表行：12–16px 圆角。
- 胶囊按钮与状态标签：999px 圆角。
- 大分区间距：12–16px；标题与内容：12–14px；列表行间距：8px；卡片内边距：12–16px。
- 中央区优先保证内容宽度；左右栏信息更紧凑，但正文字号不得低于 12px。

## 7. 顶部栏

- 顶部栏高度 52–60px，使用低透明度强模糊玻璃。
- 左侧展示薄荷叶标识、“薄荷工坊”和 `Mint Atelier`。
- 中部为全局搜索框，提示文字为“搜索内容 / 关键词 / 草稿…”，支持显示快捷键提示。
- 右侧保留通知、帮助与用户入口；图标必须有文字替代或 `aria-label`。
- 顶部栏不增加与创作无关的一级导航。

## 8. 左侧栏

### 8.1 助手身份区

- 使用 52–60px 圆形卡通女生头像，放在“小助手”标题左侧。
- 头像为肩部以上的 3D 黏土卡通形象：薄荷色帽子或发饰、深色或淡紫色头发、友好表情、蓝粉环境边缘光。
- 头像允许出现卡通脸，是背景与封面“不出现真人/脸”约束的明确例外。
- 头像右侧只显示：
  - 主标题：“小助手”
  - 副标题：“内容创作助理”
- 不再展示“本地草稿”行，也不保留其文档图标或空白占位。

### 8.2 创作流程

- 展示真实六步流程和完成百分比。
- 每步保留编号、主名称和状态摘要；编号承担进度信息，不作为装饰圆点。
- 当前步骤使用半透明蓝紫玻璃、青色边缘折射和右侧状态点。
- 已完成步骤使用勾选图标；未开始步骤降低亮度但保持可读。
- “自动化生成”过程中，仅按真实串行阶段移动当前步骤高亮。

### 8.3 草稿项目

- 草稿标题行保留“草稿项目”和“保存”。
- 每条草稿显示缩略图、标题和更新时间。
- 每条草稿最右侧固定显示“×”删除图标，不使用“···”溢出菜单。
- 删除按钮视觉尺寸 16–18px，点击目标不小于 32 × 32px；默认使用云雾白，hover/focus 切换为珊瑚红。
- 删除操作落地时必须先显示确认层，明确草稿名称，并提供“删除草稿”和“取消”；不得单击后立即不可恢复地删除。
- 键盘焦点顺序为草稿卡主体 → 删除按钮；删除按钮必须有 `aria-label="删除草稿：{草稿名称}"`。
- 底部保留“新建草稿”按钮。

## 9. 中央创作区

### 9.1 创作概览

- 概览标题使用“从关键词到可发布草稿”，同时展示流程说明与关键数量。
- 概览右侧使用 3D 粉紫笔记本与铅笔作为唯一主视觉，置于蓝粉同心光环上。
- 概览不是营销 Hero：不增加宣传口号、下载入口或与任务无关的 CTA。
- 关键数量卡保持四项：搜索结果、RAG 参考、选题候选、文章草稿。
- 数量卡使用软玻璃，图标分别使用紫、蓝、金与玫粉，但文字保持统一层级。

### 9.2 人设与关键词

- 人设和关键词区域使用连续的中强度玻璃面板，不使用亮白纸片。
- 标签始终显示，placeholder 不代替标签。
- 字数、自动缓存和格式信息紧贴字段右下方。
- 当前输入使用 1px 青色边缘和轻微内高光，不改变组件尺寸。
- “自动化生成”和“搜索热门内容”保持两个清晰动作；同一区域仅当前核心动作使用最强强调。

### 9.3 热门搜索与 RAG

- 搜索与 RAG 继续并列，宽度接近 1:1。
- 搜索区必须显示“搜索只在点击后执行，结果不会自动入库”的确认边界。
- 搜索结果保留封面缩略图、标题、来源、互动数据、时间和勾选框。
- 有封面 URL 时展示真实缩略图；缺失或失败时使用本地占位图。
- 选中态同时使用勾选图标、青色边缘和背景亮度变化，不能只靠颜色。
- RAG 区明确显示“只保存用户勾选并确认的参考内容”，并保留“加入 RAG”按钮。
- RAG 条目使用较稳定的中玻璃行，与搜索结果通过标签和来源信息区分。

### 9.4 后续阶段

- 选题、文案和 Prompt 的选中态复用搜索结果的“勾选/边缘/亮度”语法。
- 文案预览可使用更高不透明度的冷灰玻璃，但不得改成纯白纸张。
- 封面结果稳定使用 3:4 画框；生成中显示静态骨架和单一呼吸进度。
- 长文案和 Prompt 不得永久截断；折叠时必须提供明确展开入口。

## 10. 右侧模型配置与状态

- 右栏视觉重量低于中央区，但字段对比度不得降低。
- “文案生成”和“图片生成”保持独立玻璃分组，不合并为笼统的 AI 设置。
- 本地 CLI / 云端 API 使用分段控件，当前项可使用蓝紫到玫粉的克制渐变。
- API Key 始终遮蔽；不增加明文回显。
- 输入框使用软玻璃，右侧图标与下拉箭头保持 40px 以上点击区域。
- “检测本机 CLI”使用蓝粉渐变边缘，但检测只能由用户点击触发。
- 三路连接检查继续展示 xhs、Codex 和云端文本 API 的安装/鉴权/网络/真实调用状态。
- `--version` 成功不得表示整条链路正常；错误提示保留脱敏后的具体原因和下一步。

## 11. 图标、按钮与状态

### 11.1 图标

- 通用功能使用统一的 1.75–2px 圆润线性图标。
- 助手头像和概览笔记本使用 3D 黏土图标；其他面板不重复放置大型 3D 图标。
- 不使用 emoji 代替搜索、入库、生成、删除或检测等关键操作。
- 图标不能替代文字标签。

### 11.2 按钮

| 类型 | 外观 | 用途 |
| --- | --- | --- |
| 主按钮 | 极光青或蓝青玻璃、云雾白文字、柔和下投影 | 当前区域唯一主动作 |
| 强调按钮 | 蓝紫到玫粉渐变、低强度外缘光 | 自动化生成、图片生成等重点动作 |
| 次按钮 | 软玻璃、冷白边缘、亮色文字 | 重新搜索、检测、辅助操作 |
| 危险按钮 | 透明底、珊瑚红图标/文字 | 删除确认、重试阻断错误 |

- 按钮高度 38–42px，点击目标不小于 40px。
- loading 状态保持原宽，避免布局位移。
- disabled 状态取消抬升和外缘光，但文字仍可读。

### 11.3 状态语义

- 成功：极光青 + 勾选图标 + 状态文字。
- 进行中：电光蓝 + 进度图标 + 当前阶段文字。
- 选中：霓虹紫/极光青边缘 + 控件勾选 + 轻微亮度提升。
- 错误：珊瑚红状态线 + 错误图标 + 具体原因。
- 等待：薰衣草灰 + 空心状态点 + 下一步说明。

## 12. 动效

- 页面首次进入：220ms，透明度从 0 到 1，整体上移不超过 4px。
- 面板 hover：140ms，亮度增加 3–5%，上移 1–2px。
- 当前步骤：180ms 青蓝边缘过渡；状态点可进行一次性 240ms 扩散反馈。
- 背景光轨：12–18 秒低速位移，不得影响文字位置。
- 自动化生成：高亮沿真实阶段顺序移动，不模拟虚假的并行进度。
- 图片生成：1.6 秒低强度明暗呼吸，画框尺寸不变化。
- 删除草稿：确认后先更新数据，再使用 160ms 高度/透明度收起；失败时恢复条目并显示具体原因。
- `prefers-reduced-motion` 下关闭位移、循环光轨和呼吸，仅保留即时状态变化。

## 13. 可访问性与可读性

- 正文对比度至少 4.5:1，大号文字至少 3:1。
- 所有文字区域必须同时具备背景模糊与足够深的局部遮罩。
- 玻璃透明度不能成为信息分组的唯一方式；同时使用间距、标题、分隔线和对齐。
- 焦点环使用 2px 极光青或电光蓝，不移除浏览器键盘可见性。
- 状态不能只依靠红/绿或蓝/紫区分。
- 可点击卡片具备 hover、focus-visible、active、selected、disabled 和 loading 状态。
- 助手头像应提供替代文本“内容创作助理头像”；装饰性光效使用空替代文本。
- 草稿删除图标必须具有可读的无障碍名称，不能仅暴露字符“×”。

## 15. 实施顺序

3. 调整顶部栏与三列外壳，不改变功能归属和滚动模型。
4. 更新助手头像区域，移除“本地草稿”展示行。
5. 统一步骤卡、按钮、输入框、列表行、状态和焦点样式。
6. 重做中央概览、人设/关键词、搜索/RAG 和右侧模型分组的玻璃层级。
7. 为草稿卡加入删除入口；实际删除逻辑、确认对话框和错误恢复作为独立功能任务实现。

## 16. 验收标准

- 第一眼能识别出深靛蓝背景、蓝粉极光、低透明度雾面玻璃和圆润 3D 元素。
- 科技感来自光线、层次和状态反馈，而不是密集网格、硬霓虹或无关仪表盘。
- 页面仍明确属于薄荷工坊内容创作工具，不像营销页、游戏首页或通用 SaaS 后台。
- 三列结构、字段位置、用户主动触发和 RAG 确认边界保持不变。
- 左上助手区展示卡通女生头像，且不存在“本地草稿”行或空白占位。
- 草稿卡片右侧使用“×”删除入口；实现删除功能后必须具有确认、取消和失败恢复。
- 背景能够透过功能面板被感知，但长文本、配置字段和状态信息保持清晰可读。
- 当前步骤、主要按钮、选中结果、生成状态和错误状态均可在 2 秒内识别。
- 所有关键交互具有 hover、focus-visible、active、selected、disabled、loading 和 error 状态。
- 目标桌面尺寸及系统缩放下无横向内容裁切、面板重叠、按钮遮挡或状态跳动。
- 构建通过，浏览器截图与本规范和最终确认设计稿保持一致。
